# 사용 안내

## 로컬 데이터와 통신

Codexon은 로컬 Codex 세션 기록과 사용량 메타데이터를 읽습니다. 사용량 색인에는 토큰·캐시·모델·시각·상태·세션 분석에 필요한 필드가 저장됩니다. 대화 본문은 이 계산에 필요하지 않지만, 색인에는 로컬 경로와 식별자가 남습니다. 사용 한도 원장과 모델 관측 자료에는 관측 이력이 보존됩니다. 화면에 프로젝트명과 작업명이 표시될 수 있습니다.

선택 기능인 프록시를 켜면 변경 전 Codex `config.toml` **전체 원문**을 `%LOCALAPPDATA%\CacheMonitor\backups`에 백업합니다. 원래 설정에 민감한 값이 있으면 백업에도 들어갑니다. 프록시는 Codex 요청을 중계합니다. 실시간 한도는 설치된 Codex의 `app-server` 계정 RPC로 조회하며, 과거 사용량 분석은 로컬 기록을 바탕으로 합니다.

## 업데이트

새 ZIP은 새 폴더에 풀고, 이전 GUI나 프록시가 그 실행 파일을 사용하는 동안에는 이전 폴더를 보존하세요. 기존 GUI를 종료하고 새 `Codexon.exe`를 실행한 뒤 **설정 → 정보·문제 해결**에서 앱 버전을 확인합니다. 프록시는 이전 폴더의 실행 파일로 계속 동작할 수 있습니다. **설정 → 프록시**에서 별도 버전을 확인하고 **프록시 업데이트**가 표시되면 실행하세요. 기존 연결이 끝날 때까지 기다리며 유휴 WebSocket도 연결에 포함됩니다. 필요하면 Codex를 닫아 전환을 완료합니다. 새 프록시 버전과 정상 상태를 확인한 뒤 이전 폴더를 정리할 수 있습니다. 전환 중 새 연결은 잠시 실패할 수 있습니다.

## 제거

1. **설정 → 프록시**에서 프록시를 끄고 상태가 꺼짐인지 확인합니다. Codex를 다시 시작해 직접 연결을 확인합니다.
2. **설정 → 일반**에서 Windows 로그인 시 시작을 끄고 트레이의 종료로 Codexon을 닫습니다.
3. GUI와 프록시가 폴더의 실행 파일을 더 이상 사용하지 않을 때 프로그램 폴더를 제거합니다.

`%LOCALAPPDATA%\CacheMonitor`의 데이터는 별도입니다. `usage-index.sqlite`는 재생성 가능한 색인입니다. `quota-cycles.sqlite`, 모델 관측 자료, `backups`에는 관측 이력과 복구 자료가 있으므로 보존 여부를 따로 결정하세요. 실행 파일 제거만으로 이 데이터는 지워지지 않습니다.

## GUI가 열리지 않을 때 직접 연결 복구

정상적으로 남아 있는 Codexon 폴더의 실행 파일로 PowerShell에서 실행합니다.

```powershell
& 'C:\path\to\Codexon\Codexon.exe' --disable-model-observer --control-report "$env:TEMP\codexon-recovery.json"
& 'C:\path\to\Codexon\Codexon.exe' --model-observer-status
```

첫 명령에 `error`가 없어야 합니다. 두 번째 명령에서 프록시 연결 설정이 꺼진 것을 확인하고 Codex를 재시작해 일반 연결을 확인합니다. 복구가 실패하면 기존 설정과 백업을 보존한 채 오류만 비공개로 알려주세요. `config.toml` 전체나 `.codex` 폴더를 삭제하지 마세요. 결과 파일에도 경로·식별자가 있을 수 있으므로 공유 전에 확인해야 합니다.

## 안전한 문제 신고

Codexon·Windows·Codex 버전, 화면 배율, 재현 순서, 기대 결과와 실제 결과를 알려주세요. 이미지가 필요하면 가상 세션을 사용하세요. `.codex` 전체, DB, 설정 백업, `--snapshot` 원본, 가리지 않은 `--control-report`는 첨부하지 마세요. 필요한 최소 부분에서 프로젝트명·작업명·경로·식별자·비밀값을 가려주세요. 취약점은 [비공개 보안 신고](../SECURITY.md)를 이용합니다.
