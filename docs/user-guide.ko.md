# 사용 안내

## 로컬 데이터와 통신

Codexon은 로컬 Codex 세션 기록과 사용량 메타데이터를 읽습니다. 사용량 색인에는 토큰·캐시·모델·시각·상태·세션 분석에 필요한 필드가 저장됩니다. 대화 본문은 이 계산에 필요하지 않지만, 색인에는 로컬 경로와 식별자가 남습니다. 사용 한도 원장과 모델 관측 자료에는 관측 이력이 보존됩니다. 화면에 프로젝트명과 작업명이 표시될 수 있습니다.

선택 기능인 프록시를 켜면 변경 전 Codex `config.toml` **전체 원문**을 `%USERPROFILE%\.cachemonitor\model-observer\backups`에 백업합니다. 원래 설정에 민감한 값이 있으면 백업에도 들어갑니다. 프록시는 Codex 요청을 중계합니다. 실시간 한도는 설치된 Codex의 `app-server` 계정 RPC로 조회하며, 과거 사용량 분석은 로컬 기록을 바탕으로 합니다.

## 세션 오버레이와 Codex 업데이트

Codexon을 실행하고 **설정 → 세션 오버레이**를 켭니다. 오버레이는 Codex 작업 창 한 개와 해당 프로세스의 현재 화면 기록을 확인한 뒤 로컬 사용 기록을 연결합니다. 해당 Codex 창이나 오버레이 컨트롤을 사용 중일 때 표시됩니다. 불완전하거나 모호한 기록, 여러 작업 창, 원격 작업에는 다른 작업의 사용량을 대신 표시하지 않습니다.

Codex 버전 번호로 표시를 제한하지 않습니다. 화면 기록 형식이 유지되는 업데이트에는 그대로 동작하며, 형식 자체가 바뀌면 호환 작업이 필요할 수 있습니다. 현재 작업 확인에 모델 요청을 사용하지 않습니다. **설정 → 일반 → Windows 로그인 시 시작**을 켜면 로그인 때 트레이에서 시작합니다. Codex를 다시 여는 것만으로 종료된 Codexon이 실행되지는 않습니다.

## 평균 출력 속도

사용 현황 요약과 호출 상세에 **평균 출력 속도**를 `tok/s`로 표시하며, 호출 표에서는 선택 열로 추가할 수 있습니다. 오버레이에서는 최근 호출의 속도를 캐시율·비용 옆에 표시합니다. 속도를 누르면 대시보드에서 해당 호출의 소요시간을 확인할 수 있습니다.

출력 토큰(추론 포함)을 요청 관측부터 완료 응답까지의 시간으로 나눕니다. 대기·통신 시간을 포함한 호출 평균이며, 순수 스트리밍 속도는 아닙니다. 프록시 시간과 출력 토큰이 정확히 연결된 완료 호출만 측정하고, 근거 누락·충돌은 0으로 처리하지 않습니다. 사용 현황 요약은 유효 호출의 출력 합계를 같은 호출의 소요시간 합계로 나누고 측정 건수를 함께 표시합니다. 병렬 호출의 시간도 합산하므로 전체 경과시간 대비 처리량과는 다릅니다. 유효한 시간이 있는 기존 기록도 계산하며, 측정을 위한 모델 요청은 보내지 않습니다.

## 업데이트

**설정 → 정보·문제 해결 → 업데이트 확인 및 설치**를 누릅니다. 앱이 배포 파일을 자동으로 확인한 뒤 새 버전을 별도 폴더에 설치하고, 실행 검사에 통과하면 실행 경로를 전환합니다. 프록시도 같은 작업에서 업데이트합니다. 기존 연결이 남아 있으면 대기 상태가 표시되며, 진행 중인 요청을 강제 종료하거나 재전송하지 않습니다. 유휴 WebSocket도 연결에 포함됩니다. 작업을 마치고 Codex를 닫으면 전환이 진행됩니다. 새 프록시 실행에 실패하면 이전 프록시로 복원합니다. 전환 중 새 연결은 잠시 실패할 수 있습니다.

기존 ZIP 사용자는 설치 프로그램을 한 번 실행해 전환합니다. 이전 GUI가 자동 전환을 지원하지 않으면 트레이에서 Codexon만 종료한 뒤 시작 메뉴에서 다시 여세요. 설정과 기록은 기존 위치를 사용합니다. 사용 중인 이전 폴더는 그대로 보존합니다.


명시적으로 지정한 `--codex-home` 목록은 `%LOCALAPPDATA%\CacheMonitor\launch.json`에 보존됩니다. 공백이 있는 경로와 여러 홈도 업데이트 후 GUI·시작 메뉴에서 그대로 사용하며, 로그인 시 자동 실행을 켤 필요가 없습니다. 다른 홈을 사용하려면 `--codex-home`을 다시 지정하세요.

## 제거

Windows **설정 → 앱 → 설치된 앱 → Codexon → 제거**를 사용합니다. 연결 설정을 먼저 복원하며, 본체나 연결 구성요소가 사용 중이면 제거를 보류합니다. Codexon을 종료하고 기존 연결이 끝난 뒤 다시 실행하세요. 이전 ZIP 버전은 프록시와 로그인 시 시작을 끄고, 사용 중인 구성요소가 없는 것을 확인한 뒤 해당 프로그램 폴더만 제거합니다.

`%LOCALAPPDATA%\CacheMonitor`의 데이터는 별도입니다. `usage-index.sqlite`는 재생성 가능한 색인이며 `quota-cycles.sqlite`에는 사용 한도 관측 이력이 있습니다. 모델 관측 자료·프록시 상태·설정 백업은 `%USERPROFILE%\.cachemonitor\model-observer`에 있습니다. 과거 기록이나 설정 복원이 필요하면 이 폴더들을 보존하세요. 실행 파일 제거만으로 이 데이터는 지워지지 않습니다.

## GUI가 열리지 않을 때 직접 연결 복구

Windows 시작 메뉴에서 **Codexon 연결 복구**를 열고 **직접 연결로 복원**을 누릅니다. 인터넷·Codex·Codexon 본체·Qt 런타임 없이 실행됩니다. 본체의 **정보·문제 해결 → Codex 연결 복구 열기**도 같은 도구를 엽니다.

복원 완료가 표시되면 진행 중인 작업을 확인하고 Codex를 완전히 종료한 뒤 다시 엽니다. 설정 복원만으로 실제 통신 성공을 보장하지는 않습니다. 자동 판정이 정상이어도 복원을 실행할 수 있습니다. 다른 서버 주소와 로그인·나머지 설정은 보존합니다. 설정을 읽지 못하면 임의로 덮어쓰지 않고 실패를 표시합니다.

프록시 사용 시 Windows 예약 작업이 로그인 때와 1분 주기로 잠깐 실행돼 로컬 상태를 확인합니다. 두 차례 확인된 장애만 중복 없이 안내하며, 알림을 누르면 복구 도구가 열립니다. 단순 응답 지연으로 설정을 변경하거나 연결을 끊지 않습니다. 본체가 꺼져도 점검하며, 알림을 놓쳐도 시작 메뉴에서 직접 복구할 수 있습니다. 프록시를 끄면 주기 점검도 해제됩니다. 복구가 실패하면 설정과 백업을 보존하세요. `config.toml` 전체나 `.codex` 폴더를 삭제하지 마세요.

## 안전한 문제 신고

Codexon·Windows·Codex 버전, 화면 배율, 재현 순서, 기대 결과와 실제 결과를 알려주세요. 이미지가 필요하면 가상 세션을 사용하세요. `.codex` 전체, DB, 설정 백업, `--snapshot` 원본, 가리지 않은 `--control-report`는 첨부하지 마세요. 필요한 최소 부분에서 프로젝트명·작업명·경로·식별자·비밀값을 가려주세요. 취약점은 [비공개 보안 신고](https://github.com/jisoq/Codexon/security/advisories/new)를 이용합니다.

## 캐시 관리

**설정 → 캐시 관리**에서 최근 캐시 분석, 자동 유지 상태와 별도 유지 사용량을 확인합니다. 기존 미적중·저하 판정을 재사용합니다. 대화가 커져 비율만 낮아진 경우를 재사용 실패로 단정하지 않고, 모델·effort·모드·압축·30분 이상 간격을 함께 표시합니다. 선행 변화는 원인 확정이 아닙니다. 쓰기 미관측은 일반 입력이나 입력-읽기로 대체하지 않습니다.

자동 유지와 모델 변경 확인은 기본적으로 꺼져 있습니다. **Codex 훅 연결**은 선택한 홈의 `hooks.json`에 Codexon 항목만 추가하고 기존 파일을 백업합니다. Codex에서 해당 명령의 신뢰를 허용한 뒤 새 작업을 시작하세요. 설치 경로가 바뀌면 다시 연결하고 변경된 명령을 신뢰해야 합니다. 연결 해제는 Codexon 항목만 제거합니다. 다른 훅이 먼저 요청을 변경·중단하거나 해당 실행 경로가 훅을 실행하지 않으면 Codexon이 전송 차단을 보장하지 못합니다.

자동 유지에는 캐시 관리를 지원하는 관리 프록시도 필요합니다. 켜져 있을 때만 요청 문맥과 인증 헤더를 프록시 메모리에 잠시 보관합니다. 원문은 디스크에 저장하지 않으며 재시작·절전 후 새 사용자 요청을 기다립니다. 기존 조회용 계정 RPC는 모델 실행에 사용하지 않습니다. 직접 연결에서 제공하던 분석과 모델 변경 확인에 프록시를 강제하지 않습니다.

정책은 최근 60일의 같은 세션 제출 이력을 앞·뒤 구간으로 나누어 유지 횟수를 선택하고 후속 구간에서 양의 예상 이득이 없으면 **유지하지 않음**을 선택합니다. 제출 기록은 사람의 복귀가 확인됐다는 뜻이 아닙니다. 충분한 비교 자료는 독립된 두 시점 이상, 같은 모델·effort·모드의 입력/읽기/출력, 축소되지 않은 문맥에서 얻습니다. 복귀하지 않은 구간도 유지 비용에 포함합니다. 사전 유지 호출 실적은 필요하지 않습니다. 가격·입력·출력 자료가 없으면 자연 작업으로 수집하며, 미관측 쓰기는 가격 시나리오의 양 끝값으로만 비교합니다.

`benefit_lower`는 비교 가능한 복귀 요청에서 줄어든 읽기량을 일반 입력/쓰기 단가의 낮은 쪽으로 재처리했을 때의 차액입니다. 유휴가 감소의 원인이라는 증거는 아닙니다. `maintenance_upper`는 직전 읽기량이 재사용된다는 **조건부 시나리오**에서 남은 입력의 높은 쪽 단가와 출력 상한 전체를 포함합니다. 손실 없는 절감 보장이나 실제 청구액·구독 한도 차감 공식이 아닙니다. 각 세션의 현재 문맥 크기로 유지비를 다시 계산하고 과거 복귀 이득도 현재 보존 가능한 범위로 제한합니다.

출력 상한은 직전 자연 요청의 출력 토큰(추론 포함)으로 정하며 `max_output_tokens`가 총 출력·추론을 제한하는 제공자에서만 실행합니다. ACK 지시는 비용 상한이 아닙니다. 공개 OpenAI API의 이 필드 지원을 ChatGPT Codex 백엔드의 지원으로 간주하지 않습니다. **현재 ChatGPT 경로는 이 상한 지원 확인이 필요하여 자동 유지가 대기합니다.** 실제 계정 호출로 확인하는 작업은 별도 사용자 결정이 필요합니다. 대기를 피하기 위한 시험 호출은 보내지 않습니다.

설계 수명은 마지막 재사용 이후 최소 30분입니다. 요청 시작 시각을 기준으로 전송·응답 제한 30초와 스케줄 여유 1초를 빼 예약합니다. 응답 완료시각부터 30분을 새로 세지 않습니다. 매 회차는 원래 문맥에 독립 요청을 보내며 기존 도구 정의·순서·모델·effort를 보존하고 `tool_choice=none`으로 도구 실행을 제한합니다. 이전 유지 ACK를 다음 요청에 누적하지 않습니다. 원래 입력 안에서 재사용된 최소 토큰 범위만 기록하며 일부 적중을 전체 문맥 갱신으로 표시하지 않습니다.

사용자 요청은 프록시 진입 시 예약을 무효화하고 우선 진행합니다. 이미 전송한 독립 요청은 제한 시간 안에서 사용량을 수집하며 다음 회차는 중단합니다. 동일 회차와 응답 유실 요청은 재전송하지 않습니다. 인증·한도 오류, 불완전 응답, 재사용 범위 감소, 비용 미관측 또는 시나리오 상한 초과도 중단 사유입니다. 재시작·절전 후 밀린 요청을 실행하지 않습니다. 원래 대화·응답 연결·권한 설정을 변경하지 않습니다.

별도 유지 요청은 **캐시 유지** 세션으로 표시하고 원래 세션의 하위 합계, 전체 토큰·API 환산액·한도 원장에 한 번만 포함합니다. 응답이 없으면 사용량과 비용은 미확인으로 남습니다. 최근 유지 뒤 사용자 요청의 실제 입력·읽기를 함께 보여 주지만, 이 관측만으로 유지하지 않았을 때와의 인과적 순절감을 확정하지 않습니다.

모델 변경 확인은 최근 큰 재처리 부담이 예상되고 대상 모델의 최근 사용 근거가 없는 요청에만 개입합니다. 승인 대상은 세션·턴·모델이 같은 **현재 대기 요청 하나**입니다. 승인은 훅 진행 허용이며 실제 전송 완료 표시가 아닙니다. 취소·창 닫기·60초 무응답은 해당 요청을 중단합니다. 확인 UI가 없거나 시작 전 연결 장애면 통과합니다. 대기 중 UI 연결이 끊기면 저장된 취소를 먼저 확인하고 통과하되, 결정 저장소 자체를 읽을 수 없으면 취소를 뒤집지 않도록 그 요청을 중단합니다. 모델을 몰래 대체하거나 요청을 다시 제출하지 않으며 승인 안내를 대화 문맥으로 추가하지 않습니다.

보조 분석은 관측된 압축 전후 입력과 하위 작업 사용량만 비교합니다. 압축의 맥락 손실·재작업 품질, 위임할 문맥과 결과 통합 비용까지 확인해야 판단할 수 있습니다. 독립적이고 전달 문맥이 작은 작업은 위임 후보가 될 수 있지만 비용·품질 동등성을 보장하지 않으며, 설정 변경이나 자동 위임은 하지 않습니다.
