# Mac에서 Codexon 사용하기

[English](macos.md) · [README](../README.ko.md)

Mac에서도 Windows와 같은 기록 수집·계산·프록시·캐시 관리 기능을 사용합니다. 창·메뉴 막대·백그라운드 실행은 AppKit·Quartz·launchd로 구현합니다. 대상은 macOS 13 이상이며 Apple Silicon(`arm64`)과 Intel(`x86_64`) 패키지를 따로 빌드합니다.

## 설치와 실행

Mac 자산이 포함된 릴리즈에서 자신의 아키텍처에 맞는 DMG를 받습니다. 이미지 안의 **Install Codexon**을 열면 사용자 Applications 폴더에 **Codexon.app**, **Codexon Recovery.app**이 설치됩니다. 관리자 권한이나 별도 Python 설치는 필요하지 않습니다. 설치 후에는 Applications의 앱을 사용하세요.

공개 배포본은 Developer ID 서명과 Apple 공증이 필요합니다. 개발 Mac에서 만든 로컬 빌드는 별도로 표시되며, 로컬 설치·검증은 가능하지만 앱 내부 온라인 업데이트는 제공하지 않습니다. 로컬 빌드의 최소 macOS 버전은 포함된 Python과 라이브러리에서 계산하며, 빌드 보고서와 앱 정보에 기록합니다. 최근 Homebrew Python을 사용한 빌드는 macOS 26 이상을 요구할 수 있습니다. 공개 빌드는 macOS 13 기준을 충족하지 못하면 배포를 중단합니다. 빌드 도구는 개발자 인증서와 공증 자격증명이 있을 때 정식 배포본을 만들 수 있습니다. Mac 코드가 추가되었다는 사실만으로 기존 Windows 릴리즈에 Mac 다운로드가 포함되는 것은 아닙니다.

**Codexon**을 열면 기존 Codex 기록과 계정 연결을 사용합니다. 대시보드를 닫아도 메뉴 막대에서 계속 실행됩니다. **종료**는 관련 백그라운드 작업을 안전하게 정리한 뒤 끝납니다. **설정 → 일반 → 로그인 시 시작**으로 다음 로그인부터 자동 실행할 수 있습니다.

## Mac에서 달라지는 사용 방법

| 기능 | Mac 동작 |
| --- | --- |
| 세션·호출·모델·하위 작업 분석 | 공통 수집기와 계산 사용 |
| 실시간 한도·초기화 이력 | 설치된 Codex의 읽기 전용 RPC 사용. Keychain을 포함한 인증은 Codex가 처리 |
| 트레이·작업표시줄 위젯 | 메뉴 막대의 단일 항목에 잔여량과 메뉴 표시 |
| 현재 작업 오버레이 | 확인된 Codex 로컬 창을 포커스 없이 추적 |
| 세션 직접 선택 | 메뉴나 설정에서 고른 세션을 독립 패널에 고정. Codex가 숨겨져 있거나 원격이어도 사용 가능 |
| Retina·화면 선택 | 논리 좌표 사용. 선택한 화면 연결이 끊기면 주 화면으로 이동 |
| Spaces·전체 화면 | Mac 패널 속성으로 대응. 다른 앱의 창이나 Space는 변경하지 않음 |
| 알림 | 명시적으로 허용하면 시스템 알림 전달. 권한이 없어도 앱 안의 알림 이력 유지 |
| 모델 관찰·캐시 관리 | 공통 프록시·훅·운영 동의·취소·사용량 집계 사용 |
| 백그라운드 작업 | 사용자 launchd 서비스. 수집은 하나의 CollectorService가 담당 |
| 설치·업데이트·복구 | 버전별 앱 보관, 실행 링크 전환, 실패 복원, Qt와 독립된 복구 도구 |

현재 작업을 확실하게 식별하지 못하면 자동 오버레이는 다른 작업의 수치를 대신 표시하지 않습니다. **설정 → 세션 오버레이 → 표시할 세션**에서 직접 선택하세요. 고정된 패널에는 **고정** 표시가 붙습니다. 메뉴 막대의 위치는 macOS가 관리합니다.

## 권한

**설정 → 세션 오버레이 → 손쉬운 사용 설정 열기**로 시스템 설정을 열 수 있습니다. 허용하면 창 변경 감지와 Codex 창으로 휠 전달을 사용할 수 있습니다. 기본 창 탐색과 독립 패널에는 권한 요청이 필요하지 않습니다. 다른 앱의 화면을 캡처하기 위한 화면 기록 권한은 요청하지 않습니다.

**설정 → 알림 → 알림 허용**을 누를 때만 시스템 알림 권한을 요청합니다. 차단한 경우 시스템 설정에서 바꿀 수 있습니다. 설치된 앱 식별자가 없는 소스 실행에서는 앱 내부 알림 이력을 사용합니다.

## 계정과 기록

PATH·일반 CLI 설치 위치·Codex/ChatGPT 앱 리소스에서 Codex 실행 파일을 찾습니다. 사용자 지정 실행 파일은 `CODEXON_CODEX_PATH`로 지정할 수 있습니다. 홈은 `CODEX_HOME` 또는 `~/.codex`이며, 여러 홈은 `--codex-home`을 반복해서 지정합니다. 실시간 한도는 첫 번째 홈의 계정을 기준으로 합니다. 이 Mac에 기록이 없는 원격 작업의 사용량은 창 제목만으로 복원할 수 없습니다.

사용량 색인·한도 이력·실행 설정·서비스 상태는 `~/Library/Application Support/Codexon`에, 관찰 자료는 그 안의 `model-observer`에 보관합니다. UI 설정은 `~/Library/Preferences/com.cachemonitor.CacheMonitor.plist`를 사용합니다. Windows의 기존 저장 위치는 바꾸지 않습니다. Mac 프로젝트 경로는 대소문자를 보존합니다.

프록시와 자동 캐시 유지는 선택 기능입니다. 프록시를 켤 때는 Codex 연결 설정을 변경하고 검증 모델 호출을 한 번 보냅니다. 캐시 유지에는 별도의 운영 동의도 필요합니다. 설치 확인만을 위해 켜지 마세요. 한도와 중지 조건은 [사용 안내](user-guide.ko.md)를 참고하세요.

## 업데이트·복구·제거

업데이트는 **설정 → 정보·문제 해결**에서 실행합니다. Windows 전용 릴리즈가 더 최신이어도 호환되는 최신 Mac 릴리즈를 찾습니다. 받은 파일의 체크섬과 기존 앱과 동일한 Developer ID를 확인합니다. 새 버전 실행 검사가 실패하면 기존 실행 경로를 유지합니다. 기존 프록시가 연결을 처리하고 있으면 안전하게 교체할 때까지 그 실행 파일을 보존합니다. 캐시 훅은 설치된 앱의 고정 경로를 사용해 업데이트 때 명령 문자열이 바뀌지 않습니다.

대시보드나 연결에 문제가 생기면 Applications의 **Codexon Recovery**를 엽니다. Qt나 인터넷 없이 상태를 확인하고 Codexon이 관리한 연결 설정을 복구합니다. 관련 없는 설정과 계정 파일은 보존합니다. 진행 중인 Codex 작업을 끝낸 뒤 필요한 재시작을 진행하세요.

관리형 설치를 제거할 때는 복구 도구의 제거 기능을 사용합니다. 사용 중인 구성요소를 확인한 뒤 소유한 서비스와 앱 링크를 정리하고, 사용 기록과 계정 자료는 남깁니다. Applications 링크만 휴지통으로 옮기면 서비스 정리가 수행되지 않습니다. 실행·복원에 필요할 수 있는 이전 버전 폴더는 보관합니다.

## 빌드와 검증

환경 준비와 명령은 [CONTRIBUTING](../CONTRIBUTING.md)을 따릅니다. `tools/mac_build.py`는 앱 3종·DMG·체크섬·빌드 보고서를 만듭니다. 변경 중인 소스는 로컬 검증에 한해 `--allow-dirty`로 빌드할 수 있고, 공개 빌드는 커밋한 소스를 사용합니다.

`macos.yml`은 두 아키텍처의 개발용 앱을 검증합니다. 공개 배포는 개발자 서명과 공증 자격증명을 저장한 후 `macos-release.yml`로 진행합니다. 이 워크플로는 소스·설치·복구·앱 조작을 검사하고, 앱과 DMG를 공증한 뒤 명시적으로 게시를 선택한 경우에만 릴리즈 자산을 올립니다.

이미 사용자가 자동 설치를 승인한 작업은 설치기 실행 파일에 `--yes --source <앱 두 개를 담은 폴더> --report <새 보고서 경로>`를 전달할 수 있습니다. 로컬 임시 서명 빌드는 `--allow-ad-hoc`도 필요합니다. 설치 검사는 `--isolated-install --install-root <임시 경로> --applications <임시 앱 폴더> --no-launch`로 격리합니다. 이 옵션들은 OS 권한이나 프록시·캐시 사용 동의를 대신하지 않습니다.

`tools/mac_verify.py`는 실제 앱의 설치·재설치·실패 복원·독립 복구·기록 보존 제거를 검사합니다. `tools/verify_macos_desktop.py`는 다른 앱을 변경하지 않고 Mac 패널과 메뉴 동작을 확인합니다. Qt offscreen 검사는 공통 렌더링·조작을 확인합니다. 실제로 보이는 Codex 창 추적, 여러 물리 모니터, 시스템 알림 전달, 재부팅 후 로그인은 해당 환경에서 별도로 검증해야 합니다.
