# 요청 모드 관측과 분류

2026-10-19 10:53 KST에 로컬 기록을 읽기 전용으로 조사했습니다. 요청과 응답의 서비스 등급은 별도로 분류합니다.

| 수신 위치 | 실제 수신 값 | 처리 |
| --- | --- | --- |
| 적용 설정, 요청 본문 | `default` | Standard로 계산하고 오버레이 모드 표시는 생략 |
| 적용 설정, 요청 본문 | `priority` | Fast로 계산하고 `fast` 표시 |
| 설정 변경 로그 | `Some(None)` | 명시적인 설정 해제로 처리하고 Standard 적용 |
| 설정 변경 로그 | `None` | 변경 없음으로 처리하고 해당 시점의 기존 설정 유지 |
| 호출 문맥, 사용량 기록, 요청 본문 | 필드 없음 | 해당 호출의 적용 설정이나 확인된 상속 근거로 판정 |
| 응답 본문 | `default`, `auto`, 빈 값 | 응답 정보로만 보관하며 요청 모드 판정에 사용하지 않음 |

요청의 필드 누락은 Standard를 뜻하지 않습니다. 근거가 부족하거나 충돌하면 미확인을 유지합니다. 새 문자열은 원문을 보존하고 미지원 값으로 구분합니다. 잘못된 자료형도 별도로 집계합니다.

조사 범위는 색인 이벤트 147,813개, 요청 시도 32,696개, 설정 로그 6,083개입니다. 원본 파일 1,172개 중 376개를 읽었습니다. 나머지 796개는 해당 경로에 없어 원문 확인에서 제외했습니다.

요청 본문에서 필드 누락은 25,971건, `default`는 527건, `priority`는 6,198건이었습니다. 응답에서는 `default` 28,710건, `auto` 3,937건, 빈 값 49건을 확인했습니다. 각 요청 시도의 마지막 저장 관측을 한 건으로 셌습니다.

## 비용 누락 원인

확인한 두 대화에서는 적용 설정에 `default`가 있었습니다. 호출 문맥과 설정의 시각이 약 1ms 달라 연결되지 않았습니다. 기존 코드는 두 이벤트의 시각이 정확히 같아야 해당 호출에 설정을 적용했습니다.

동일 대화의 원본에서 바로 이어진 적용 설정을 연결하도록 수정했습니다. 중간에 다른 원본 이벤트가 있으면 현재 호출에 소급 적용하지 않습니다.

두 대화의 원본을 재계산해 누락된 127개 호출의 비용을 복구했습니다. 비교한 183개 호출의 토큰 값은 수정 전후 동일했습니다.
