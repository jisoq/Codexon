# CODEX·ON

[English](README.md) · [한국어](README.ko.md)

**호출한 모델과 응답한 모델, 같은지 확인하세요.** Codexon은 호출 모델과 응답 모델의 불일치를 감시해 모델 라우팅 징후를 확인할 수 있는 Windows 앱입니다. Codex 창 위에서 모델명과 사용량을 확인하고, 세션별 토큰과 API 환산 비용, 남은 사용 한도를 함께 살펴볼 수 있습니다.

![샘플 세션으로 실행한 Codexon 오버레이](docs/media/overlay-sample.png)

- **호출 모델과 응답 모델의 불일치를 감시합니다.** 요청·응답에 기록된 모델명을 비교해, 호출한 모델과 다른 모델이 응답한 경우를 확인합니다.
- 작업 중 최근 호출의 토큰, 캐시율, API 환산 비용을 오버레이에서 확인합니다.
- 세션에서 개별 호출까지 살펴보고, 확인된 하위 작업의 사용량을 세션 합계에 포함합니다.
- 모델·추론 수준·서비스 등급별 사용량을 비교하고, 각 결과에 포함된 호출을 살펴봅니다.
- 남은 사용량과 초기화 시각을 확인합니다. 대시보드를 닫아도 트레이와 작업표시줄 위젯에서 잔여량을 볼 수 있습니다.

비용은 **실제 청구액이 아닌 API 가격 기준 환산액**입니다. 모델 관찰은 요청·응답에 기록된 모델명을 비교합니다. 실시간 한도 조회는 설치된 Codex의 app-server와 계정 연결을 사용합니다.

| 기능 | 필요한 조건 |
| --- | --- |
| 세션별 토큰·캐시·API 환산 비용 | 로컬 Codex 사용 기록 |
| 남은 사용 한도·초기화 시각 | 사용 가능한 Codex 계정 연결 |
| 세션 오버레이 | Codexon 실행, 오버레이 켜짐, 식별 가능한 Codex 작업 창 한 개 |
| 요청·응답 모델 비교 | 선택 기능인 프록시와 동일 요청에 연결된 완료 응답 근거 |

설치 대상은 **Windows 10/11 x64**입니다. Python·Qt와 독립 연결 복구 도구가 설치 파일에 포함됩니다. Codex 계정 연결을 이용하며, Codexon을 위해 별도의 API 키를 발급할 필요는 없습니다.

## 시작하기

**AI에게 설치를 맡기려면** 이 저장소 링크를 주고 [AI / LLM 전용 설치 안내](INSTALL.md)를 따라 설치하도록 요청하세요. 다운로드 검증부터 첫 실행, 선택 기능인 모델 관찰, 소스 실행 환경 구축까지 안내합니다.

1. [Releases](https://github.com/jisoq/Codexon/releases)에서 `Codexon-Setup.exe`를 받습니다.
2. 설치 프로그램을 실행합니다. 관리자 권한이나 별도 Python 설치가 필요하지 않습니다.
3. 시작 메뉴에서 **Codexon**을 엽니다. 로그인 후에도 자동 실행하려면 **설정 → 일반 → Windows 로그인 시 시작**을 켭니다.

앱 내부 업데이트·시작 메뉴 등록·제거 기능을 갖춘 설치형으로 배포합니다.

Codex 기록이 아직 없다면 Codex를 먼저 사용한 뒤 대시보드를 갱신하세요. **설정 → 일반 → 언어**에서 한국어·English를 선택하면 다음 실행부터 적용됩니다. 대시보드를 닫아도 트레이에서 계속 실행되며, 완전히 종료하려면 트레이의 종료 메뉴를 사용합니다.

## 선택 기능: 요청·응답 모델 관찰

**설정 → 프록시 → 프록시 사용**을 켜면 요청 모델과 응답에 기록된 모델을 비교합니다. 켤 때 기존 Codex 계정 연결로 검증 호출을 한 번 보냅니다. 설정이 완료되면 Codex를 다시 시작해야 연결 변경이 적용됩니다. 세션 기록·비용 분석·사용 한도 화면은 프록시 없이도 사용할 수 있습니다.

완료된 요청과 응답을 신뢰할 수 있게 연결한 경우에만 모델 일치·불일치를 표시합니다. 근거 누락이나 충돌은 불일치로 취급하지 않습니다. 응답에 기록된 모델명만으로 실제 처리 하드웨어나 내부 모델 구현까지 확인할 수는 없습니다.

## Codex 업데이트와 오버레이

**설정 → 세션 오버레이**에서 켭니다. 오버레이는 허용된 버전 목록 대신 실행 중인 Codex 프로세스와 현재 작업의 화면 기록을 확인합니다. 버전 번호만 바뀌었다는 이유로 표시를 차단하지 않습니다. Codexon이 실행 중이어야 하며, 해당 Codex 창이나 오버레이 컨트롤을 사용 중일 때 표시됩니다. Codex를 다시 여는 것만으로 종료된 Codexon이 실행되지는 않습니다.

화면 기록이 불완전하거나 Codex 작업 창이 여러 개일 때, 원격 작업이거나 로컬 기록을 하나로 식별할 수 없을 때는 다른 작업의 사용량을 대신 표시하지 않습니다. 향후 Codex의 화면 기록 형식 자체가 바뀌면 추가 호환 작업이 필요할 수 있습니다. 현재 작업을 확인하기 위한 모델 요청은 보내지 않습니다.

## 업데이트와 연결 복구

**설정 → 정보·문제 해결 → 업데이트 확인 및 설치**를 사용합니다. 배포 파일을 검증한 뒤 앱과 연결 구성요소를 함께 업데이트하며, 설정과 기록은 보존합니다. 기존 ZIP 사용자는 Setup을 한 번 실행해 설치형으로 전환할 수 있습니다.

설치 프로그램은 버전마다 별도 폴더를 사용합니다. 실행 중인 프록시는 기존 연결이 끝난 뒤 교체하며, 요청을 강제 종료하거나 재전송하지 않습니다. 실행 중인 구성요소나 복원 경로에서 사용하는 이전 폴더는 보존하세요.

Codex가 연결되지 않으면 **시작 메뉴 → Codexon 연결 복구 → 직접 연결로 복원**을 사용합니다. 이 도구는 인터넷·대시보드·실행 중인 프록시 없이 독립적으로 동작합니다. 복원 성공 후 진행 중인 작업을 마치고 Codex를 다시 시작해야 연결 변경이 적용됩니다. 설정 복원이나 로컬 프록시 응답만으로 실제 모델 통신 성공을 보장하지는 않습니다.

프록시 사용 중에는 예약 점검이 반복 확인된 로컬 장애를 알려줍니다. 점검이 연결 설정을 자동 변경하거나 모델 요청을 보내지는 않습니다.

## 로컬 데이터와 제거

사용량 색인과 한도 이력은 `%LOCALAPPDATA%\CacheMonitor`에, 모델 관측 자료·프록시 상태·설정 백업은 `%USERPROFILE%\.cachemonitor\model-observer`에 저장됩니다. 이전 내부 이름은 호환성을 위해 유지합니다. 프로그램 업데이트나 제거만으로 이 기록을 삭제하지 않습니다.

**Windows 설정 → 앱 → 설치된 앱 → Codexon → 제거**를 사용합니다. 관리 중인 연결 설정을 먼저 복원하고, 사용 중인 구성요소가 있으면 제거를 보류합니다. 설정 백업에는 민감한 값이 포함될 수 있으므로 문제 신고에 백업이나 가리지 않은 기록을 첨부하지 마세요. 데이터 처리와 복구의 자세한 내용은 [사용 안내](docs/user-guide.ko.md)에 있습니다.
