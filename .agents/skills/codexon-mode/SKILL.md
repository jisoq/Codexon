# Codexon 작업방식

이 프로젝트에서 확인된 사용자의 요구와 반복 교훈을 적용한다.
작업 범위와 실행 권한은 현재 요청에서 판단한다.
검사 명령과 배포 절차는 [저장소 지침](../../../AGENTS.md)과 [검증 정책](../../../docs/verification.md)을 따른다.

## 실제 사용 동작을 완료 기준으로 삼기

- 성능 작업은 사용자가 지적한 동작의 시작과 완료를 먼저 정한다.
  탭 열기와 세션 전환은 각 결과가 화면에 반영되는 시점까지 확인한다.
- 접근 가능한 실제 데이터로 보고된 증상을 확인한다.
  예제 데이터만 확인했다면 실제 사용에서 해결됐다고 보고하지 않는다.
- 최적화는 불필요한 조회, 계산, 화면 생성을 줄이는 방법부터 검토한다.
  표시 방식 변경이 재조회나 재계산을 늘리는지도 확인한다.
- 최초 로딩과 기존 결과 갱신을 구분한다.
  갱신 중에는 기존 결과와 배치를 유지한다.
  로딩 표시만으로 대기시간 개선을 주장하지 않는다.

## 같은 실패가 반복되면 이전 수정의 전제를 확인하기

- 같은 증상이나 검사가 재발하면 이전 수정과 새 실패의 증거를 대조한다.
  공통 원인인지 확인하기 전에 대기시간 증가나 개별 예외를 반복하지 않는다.
- 비동기 실패는 데이터 준비, 대상 화면 생성, 실제 표시를 구분해 추적한다.
  상위 컨테이너 준비나 다른 화면의 유휴 상태를 대상 화면의 완료로 간주하지 않는다.
- CI 실패는 최초 실패 지점부터 확인한다.
  앱 동작, 검사 코드, 실행 환경, 게시 절차의 문제를 구분한다.
  뒤따른 작업 생략과 최종 판정 실패를 별도 원인으로 세지 않는다.
- 재실행 성공만으로 원인 해결을 선언하지 않는다.
  코드, 데이터, 환경에서 달라진 조건을 확인한다.
  원인을 설명할 증거가 없으면 미확정으로 남긴다.
- 반복 결함은 공통 구조나 기존 검사로 예방할 수 있는지 먼저 검토한다.
  확인된 실패를 잡지 못하는 규칙이나 검사를 추가하지 않는다.

## 완료 보고를 확인한 범위에 맞추기

- 코드 반영, 회귀 검사 통과, 설치본 동작 확인을 구분해 보고한다.
  테스트 개수를 실제 사용성이나 성능 개선의 근거로 대신하지 않는다.
- 남은 문제와 미측정 항목을 완료 주장 옆에 적는다.
  작업 재개 시 원래 사용자 목표와 현재 증거를 대조한다.
  이전 계획의 항목을 끝냈다는 이유만으로 목표 달성을 선언하지 않는다.
